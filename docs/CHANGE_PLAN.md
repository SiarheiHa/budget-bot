# CHANGE_PLAN.md

План предлагаемых изменений по итогам аудита проекта.

- Ветка: `fix/audit-quick-wins` (база — `deploy`)
- Дата создания: 2026-11-08
- Порядок прохождения: **A → B → D → C**

## Правила работы с планом

1. Каждый пункт обсуждается отдельно: суть, зачем нужно, риск, затрагиваемые файлы, способ проверки.
2. Изменение вносится только после явного одобрения.
3. После правки запускаются `npm test` и `npm run lint`.
4. Для UI/поведения даётся пошаговая инструкция для ручной проверки в тестовом боте и тестовой таблице.
5. Коммит делается после успешной проверки, сообщение — на английском.
6. Принятый пункт отмечается `[x]`.
7. Если пункт отклонён — он удаляется из этого файла.
8. Если изменение не прошло тест — откат; далее доработка или удаление пункта по решению.
9. По завершении файл удаляется, ветка вливается в `deploy`, затем `main` (`--ff-only`).
10. Push в `deploy` и `main` выполняет пользователь.

## A. Баги и риски

### A1. Formula injection в примечании
- **Проблема:** запись идёт с `valueInputOption: "USER_ENTERED"`, а `note` — свободный текст. Строка вида `=IMPORTXML(...)` попадёт в таблицу как формула.
- **Зачем:** безопасность данных и таблицы.
- **Риск:** средний; нужно не сломать обычные примечания, начинающиеся с дефиса.
- **Файлы:** `src/sheets.js`.
- **Проверка:** unit-тест на санитизацию; ручная запись примечания `=1+1` и проверка, что оно сохранено текстом.
- **Статус:** [x]

### A2. Гонка AI и ручного `/add`
- **Проблема:** пока идёт запрос к AI, пользователь может запустить `/add`; после ответа AI делает `state.set(...)` и затирает состояние ручного диалога.
- **Зачем:** не терять введённые пользователем данные.
- **Риск:** средний; нужно аккуратно проверять актуальность состояния после `await`.
- **Файлы:** `src/handlers/aiHandler.js`.
- **Проверка:** unit-тест на то, что поздний ответ AI не перезаписывает появившееся состояние `/add`.
- **Статус:** [x]

### A3. Незаякоренные regex кнопок
- **Проблема:** `bot.onText(/Добавить транзакцию/)`, `/Показать баланс/`, `/❌ Отмена/` срабатывают на любое сообщение, содержащее фразу, включая примечание.
- **Зачем:** избежать ложного запуска сценариев и потери данных.
- **Риск:** низкий.
- **Файлы:** `src/handlers/startHandler.js`, `src/handlers/cancelHandler.js`.
- **Проверка:** unit-тесты на точное совпадение; ручная отправка примечания с этими фразами.
- **Статус:** [x]

### A4. Переводы в `/add` пишутся неполно
- **Проблема:** ручной список категорий включает `transfer`, но флоу сохраняет одну строку с одним кошельком.
- **Зачем:** корректность данных по переводам.
- **Риск:** высокий с точки зрения влияния на данные; нужно продуктовое решение: скрыть переводы из `/add` или реализовать пару «откуда/куда».
- **Файлы:** `src/handlers/addHandler.js`, `src/sheets.js`, `src/keyboards.js`, `src/messages.js`.
- **Проверка:** обсудить сценарий; unit-тесты + ручная запись.
- **Статус:** [x]

### A5. `/balance` оставляет сообщение «Запрашиваю балансы...»
- **Проблема:** после `LOADING` отправляется новое сообщение с результатом, а `LOADING` остаётся в чате.
- **Зачем:** чистый чат и меньше путаницы.
- **Риск:** низкий.
- **Файлы:** `src/handlers/balanceHandler.js`, `src/messages.js`.
- **Проверка:** unit-тесты на удаление `LOADING` и отправку результата; ручной `/balance`.
- **Статус:** [x]

### A7. `/cancel` после истечения TTL молчит
- **Проблема:** `state.get` удаляет протухшее состояние и возвращает `null`, ответ пользователю не отправляется.
- **Зачем:** понятная обратная связь.
- **Риск:** низкий.
- **Файлы:** `src/handlers/cancelHandler.js`, `src/state.js`.
- **Проверка:** unit-тест на `/cancel` с истёкшим state; ручная проверка.
- **Статус:** [x]

### A8. `DEBUG=false` включает debug-логи
- **Проблема:** `if (process.env.DEBUG)` считает строку `"false"` истиной.
- **Зачем:** предсказуемое управление логами.
- **Риск:** низкий.
- **Файлы:** `src/logger.js`.
- **Проверка:** unit-тест на разбор значений; ручной запуск с `DEBUG=false`.
- **Статус:** [x]

### A9. Слишком мягкий `parseAmount`
- **Проблема:** `parseFloat` принимает `"12abc"` как `12`, `"1,2,3"` как `1.2`.
- **Зачем:** защита от ошибочного ввода суммы.
- **Риск:** низкий; нужно сохранить поддержку пробелов, запятой и отрицательных значений.
- **Файлы:** `src/utils.js`.
- **Проверка:** unit-тесты на валидные и невалидные строки; ручной ввод в `/add`.
- **Статус:** [x]

### A10. Старая AI-карточка при `/add`
- **Проблема:** при повторном `/add` у AI-сообщения снимается только inline-клавиатура, само сообщение остаётся; ручная карточка удаляется.
- **Зачем:** единообразное поведение и чистый чат.
- **Риск:** низкий.
- **Файлы:** `src/handlers/addHandler.js`.
- **Проверка:** unit-тест; ручной сценарий «AI-карточка → /add».
- **Статус:** [x]
