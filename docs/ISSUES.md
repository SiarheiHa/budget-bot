# ISSUES.md

## 1. Найденные при ручном тесте

### 1.1 Сумма
- **Проблема:** при вводе букв вместо числа в шаге `amount` ранее не показывалась ошибка. Сейчас исправлено частично - нужно проверить в текущей версии.
- **Ожидание:** при невалидном вводе показывать `AMOUNT_INVALID`, оставаться на шаге `amount`, не завершать диалог.
- **Где смотреть:** `src/utils.js` (`parseAmount`), `src/handlers/addHandler.js` (блок `step === "amount"`)
- **Статус:** правка внесена (`3e94ead`), требует повторной проверки

### 1.2 Категория/кошелёк вручную
- **Проблема:** если ввести значение не из списка категорий/кошельков вручную, ранее диалог прерывался с сообщением `MESSAGES.ADD_TRANSACTION.ERROR` ("Произошла ошибка при добавлении"), `state` очищался.
- **Причина:** при неверном выборе использовался `newState.categories`/`newState.wallets`, но `newState` ещё не был создан/присвоен в этих ветках — обращение к нему вызывало исключение и попадало в общий `catch`.
- **Исправление:** при неверном выборе использовать `userState.categories`/`userState.wallets`.
- **Статус:** исправлено (`31e08e3`), проверено — работает корректно

### 1.3 UX клавиатуры
- **Проблема:** на этапах `date`, `amount`, `note` ReplyKeyboard сворачивается, пользователю приходится вручную разворачивать её/ставить курсор в поле ввода.
- **Идеи для обсуждения:**
  - `force_reply: true` вместо/вместе с ReplyKeyboard
  - Для шага `amount` рассмотреть "цифровой" UX (либо оставить ReplyKeyboard с кнопкой "Отмена", либо иное решение)
  - Для `note` - обсудить, что уместнее
- **Где смотреть:** `src/keyboards.js`, `src/handlers/addHandler.js`
- **Статус:** на обсуждении, правок пока не вносить

## 3. Расхождения с исходным описанием
- **Точка входа**: в описании `src/index.js` называется точкой входа, но `start` = `node server.js`, `dev` = `nodemon src/index.js`. Фактически для прод-запуска используется `server.js` (импортирует `src/index.js`). `src/index.js` только логирует запуск.
- **main в package.json**: приведён в соответствие с `server.js`
- **cancelHandler**: обрабатывает `/cancel` и `❌ Отмена` **без** middleware доступа
- **balanceHandler/addHandler**: экспортируют `handleBalanceCommand`/`handleAddCommand`, используются из startHandler
- **README.md**: ранее пустой, теперь заполнен
- **logger**: минимальный консольный
- **Кнопки меню**: `(/add)`, `(/balance)` убраны из текста кнопок
- **Доступ**: `ALLOWED_USERS` обязателен, при пустом/отсутствии падает с ошибкой
- **TTL состояний**: добавлен 15 минут с уведомлением пользователя при истечении
