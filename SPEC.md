# SPEC.md

Аудит в процессе. Буду дополнять по мере изучения кода.

## 1. Общее
- Назначение: персональный учёт финансов через Telegram
- Хранилище: Google Sheets
- Точка входа: `server.js` -> `src/index.js` -> `src/bot.js`
- Режим: polling (`new TelegramBot(token, { polling: true })`)

## 2. Архитектура (as-is)
```
src/
├── bot.js           # инициализация бота, deps, регистрация хендлеров
├── config.js        # валидация env, экспорт config
├── sheets.js        # Google Sheets API
├── state.js         # Map состояний пользователей
├── utils.js         # парсинг/валидация/доступ
├── keyboards.js     # клавиатуры
├── messages.js      # тексты
├── logger.js        # консольный логгер
├── handlers/
│   ├── startHandler.js
│   ├── addHandler.js
│   ├── balanceHandler.js
│   └── cancelHandler.js
└── index.js         # лог о запуске
```

## 3. Конфиг
Обязательные: `BOT_TOKEN`, `SPREADSHEET_ID`
Опциональные: `ALLOWED_USERS` (csv), `GOOGLE_CREDENTIALS_B64`, `NODE_ENV`, `DEBUG`

## 4. Google Таблица
Листы:
- `Categories!A2:A50` — категории
- `Wallets!B2:D` — имя, баланс, валюта (берётся getBalances)
- `Wallets!B2:B20` — имена (getWallets)
- `Transactions!A:G` — транзакции. При записи в A,G + пустые B,D (чтобы не затирать формулы)

## 5. Флоу
### /start
Меню с кнопками "Добавить транзакцию (/add)", "Показать баланс (/balance)"

### /add (многошаговый)
1. date — `parseDateDDMMYYYY` (поддерживает разделители, короткие форматы, 2-значный год)
2. amount — `parseAmount` (запятая/точка, пробелы)
3. category — выбор из загруженных из таблицы
4. wallet — выбор из загруженных из таблицы
5. note — ввод или `-` для пустого
Сохранение через `sheets.appendTransaction` с `valueInputOption: "USER_ENTERED"`

### /balance
`getBalances()` парсит B2:D, приводит баланс к числу, фильтрует пустые имена

### Отмена
`/cancel` или кнопка `❌ Отмена` — очищает state, возврат в меню

## 6. Состояние
`state.js` — in-memory Map. Структура при `/add`:
```js
{ step: 'date'|'amount'|'category'|'wallet'|'note', data: {...}, categories: [], wallets: [], _ts: <timestamp> }
```
TTL: **15 минут**. При истечении `getUserState` удаляет состояние и отправляет пользователю сообщение о истечении сессии с возвратом в главное меню. Очищается через `state.del(chatId)` по завершению/отмене. `updateUserState` обновляет `_ts`.

## 7. Доступ
`checkAccess` — сравнивает chatId со списком. `ALLOWED_USERS` теперь **обязателен** - если пустой/не задан, `config.js` падает с понятной ошибкой при старте (и в production делает `process.exit(1)`). Middleware шлёт `ACCESS_DENIED` при запрете. В тестовом `.env` задан `ALLOWED_USERS` - доступ разрешён только указанному ID.

## 8. Наблюдения (первые)
- `addHandler` в `bot.on("message")` ловит все сообщения. Фильтр: если нет state ИЛИ текст начинается с `/` — выход. Кнопка "Отмена" проверяется отдельно (и в cancelHandler тоже есть)
- В `startHandler` при клике по кнопкам вызываются `handleAddCommand`/`handleBalanceCommand` напрямую (оба с проверкой доступа)
- `cancelHandler` обрабатывает `/cancel` и `❌ Отмена` **без** проверки доступа (решение: вариант А). Неавторизованный пользователь не может самостоятельно создать `state` диалога, поэтому доступ к отмене не критичен
- `sheets.js` при `test` аргументе делает быструю проверку
- Логгер минимальный, без ротации
- README.md пустой
- В `package.json` main: `index.js`, но запуск через `server.js`
- `config.js` при отсутствии обязательных переменных в production делает `process.exit(1)`, в dev кидает ошибку
- `addHandler` при ошибке очищает state и показывает главное меню
- Кнопка в главном меню называется "Добавить транзакцию (/add)" - текст включает команду, но хендлер ловит по подстроке "Добавить транзакцию"

## 11. Расхождения с budget описание.md
- **Точка входа**: в описании `src/index.js` называется точкой входа, но в `package.json` `start` = `node server.js`, `dev` = `nodemon src/index.js`. Фактически для прод-запуска используется `server.js` (который импортирует `src/index.js`). `src/index.js` только логирует запуск.
- **main в package.json**: `main: "index.js"`, но реальный запуск идёт через `server.js`. Несоответствие.
- **Иммутабельность состояний**: в описании упоминается "иммутабельное обновление состояний", в `addHandler` используется spread (`{ ...userState, step: ..., data: {...} }`) - частично соответствует, но не везде.
- **Доступ**: `cancelHandler` обрабатывает `/cancel` и `❌ Отмена` **без** middleware доступа - в описании не упомянуто. Также при пустом `ALLOWED_USERS` в текущем `checkAccess` доступ **заблокирован** (есть закомментированный вариант разрешить всем).
- **Кнопки меню**: в `keyboards.js` текст кнопок `"Добавить транзакцию (/add)"`, `"Показать баланс (/balance)"` (с указанием команд) - в описании упоминаются просто кнопки.
- **balanceHandler**: экспортирует `handleBalanceCommand` (используется из startHandler) - не отражено в описании.
- **addHandler**: экспортирует `handleAddCommand` - не отражено.
- **README.md**: пустой, в описании структуры он не упоминается как пустой.
- **logger**: минимальный консольный, в описании просто упомянут.
- **state.update**: в `state.js` есть `updateUserState`, но в коде бота/хендлерах не используется.
