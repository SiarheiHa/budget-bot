# **Энциклопедия проекта: Telegram Bot для учёта финансов**

## **🎯 Общее описание проекта**

Это Telegram-бот для персонального учёта финансов, который хранит все данные в Google Таблицах. Бот позволяет пользователям:

* Добавлять транзакции через многошаговый диалог  
* Просматривать текущие балансы по кошелькам  
* Работать с категориями и валютами

Технический стек: Node.js, Telegram Bot API, Google Sheets API, Render (хостинг)

## **🔧 Ключевые модули и их назначение**

### **1\. Основные модули**

`src/index.js`

* Точка входа приложения  
* Импортирует и запускает бота  
* Выводит сообщение о успешном запуске

`src/bot.js`

* Создает экземпляр Telegram бота  
* Инициализирует все зависимости  
* Регистрирует обработчики команд  
* Центральный хаб приложения

`src/config.js`

* Централизованное управление настройками  
* Загрузка переменных окружения  
* Валидация обязательных настроек  
* Поддержка разных сред (development/production)

### **2\. Обработчики команд (`src/handlers/`)**

`startHandler.js`

* `/start` \- приветственное сообщение и главное меню  
* Обработка кнопок "Добавить транзакцию" и "Показать баланс"  
* Использует middleware для проверки доступа

`balanceHandler.js`

* `/balance` \- показ текущих балансов кошельков  
* Получение данных из Google Sheets  
* Форматирование и вывод балансов с валютами

`addHandler.js`

* `/add` \- многошаговый диалог добавления транзакции  
* Последовательность шагов: дата → сумма → категория → кошелёк → примечание  
* Валидация ввода на каждом шаге  
* Иммутабельное обновление состояний

`cancelHandler.js`

* `/cancel` и кнопка "❌ Отмена" \- отмена текущей операции  
* Очистка состояния пользователя  
* Возврат в главное меню

### **3\. Сервисные модули**

`src/sheets.js`

* Работа с Google Sheets API  
* Чтение категорий, кошельков, балансов  
* Запись транзакций  
* Поддержка двух способов аутентификации (файл/BASE64)

`src/state.js`

* Управление состояниями пользователей  
* Хранение в памяти (Map)  
* Функции для установки, получения, обновления и очистки состояний

`src/utils.js`

* Парсинг дат с поддержкой разных форматов и разделителей  
* Парсинг денежных сумм  
* Форматирование валют  
* Middleware для проверки прав доступа  
* Валидация и санитизация текста

`src/keyboards.js`

* Главная клавиатура меню  
* Клавиатура с кнопкой отмены  
* Функции для показа/скрытия клавиатур

`src/messages.js`

* Все текстовые сообщения бота  
* Группировка по функциональным блокам  
* Централизованное управление текстами

## **⚙️ Конфигурация и настройки**

### **Переменные окружения**

| Переменная | Назначение | Обязательная |
| :---- | :---- | :---- |
| `BOT_TOKEN` | Токен Telegram бота от @BotFather | ✅ |
| `SPREADSHEET_ID` | ID Google Таблицы | ✅ |
| `ALLOWED_USERS` | Список ID разрешённых пользователей (через запятую) | ❌ |
| `GOOGLE_CREDENTIALS_B64` | Закодированные ключи Google API в Base64 | ❌ |
| `NODE_ENV` | Режим работы (development/production) | ❌ |

### **Структура Google Таблицы**

Лист "Categories"

* `A2:A50` \- список категорий расходов/доходов

Лист "Wallets"

* `B2:B20` \- названия кошельков  
* `C2:C20` \- балансы кошельков  
* `D2:D20` \- валюты кошельков

Лист "Transactions"

* `A:G` \- транзакции (дата, пусто, сумма, пусто, категория, кошелёк, примечание)

## **🔄 Рабочие процессы**

### **Диалог добавления транзакции**

1. Команда `/add` → загрузка категорий и кошельков  
2. Шаг даты → парсинг в формате ДД.ММ.ГГГГ (с разными разделителями)  
3. Шак суммы → парсинг чисел с запятыми/точками  
4. Шаг категории → выбор из заранее загруженных категорий  
5. Шаг кошелька → выбор из доступных кошельков  
6. Шаг примечания → ввод текста или "-" для пустого значения  
7. Сохранение → запись в Google Таблицу

### **Система состояний**

* Каждый пользователь имеет свой объект состояния  
* Состояние содержит текущий шаг, введенные данные, списки категорий/кошельков  
* Очищается после завершения диалога или отмены

### **Обработка ошибок**

* Многоуровневая обработка (уровень данных \+ уровень бизнес-логики)  
* Логирование ошибок с контекстом  
* Уведомление пользователей о ошибках  
* Гарантированный возврат в главное меню при ошибках

## **🚀 Развертывание на Render**

### **Подготовка проекта**

1. Создание `server.js` для health-чеков  
2. Настройка `package.json` с правильными скриптами  
3. Проверка `.gitignore` (исключение чувствительных файлов)

### **Процесс деплоя**

1. Создание Web Service в Render  
2. Подключение GitHub репозитория  
3. Настройка переменных окружения  
4. Настройка Build Command: `npm install`  
5. Настройка Start Command: `npm start`  
6. Health Check Path: `/health`

### **Аутентификация Google Sheets**

* Локально: через `credentials.json`  
* На хостинге: через `GOOGLE_CREDENTIALS_B64` (Base64 encoded)

## **💡 Архитектурные решения и проблемы**

### **Принятые архитектурные решения**

1. Разделение ответственности \- каждый модуль отвечает за свою задачу  
2. Инъекция зависимостей \- явная передача зависимостей в обработчики  
3. Многоуровневая обработка ошибок \- разные уровни для разных типов ошибок  
4. Centralized configuration \- единый источник настроек
