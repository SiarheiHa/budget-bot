# AGENTS.md

## Проект
Telegram-бот учёта бюджета. Данные хранятся в Google Таблицах.
Стек: Node.js (ESM), node-telegram-bot-api, googleapis.

## Ветки
- `deploy` — рабочая/основная ветка, актуальная база для изменений.
- `main` — релизная ветка; перед работой должна быть синхронизирована с `deploy`
  (`git switch main && git merge --ff-only deploy`), push делает пользователь.
- Новые фичи и правки — в отдельной ветке от `deploy` (`feat/...`, `fix/...`, `chore/...`).
- Перед началом работы всё равно уточнять ветку у пользователя. Старые ветки не использовать.

## Документация
- `docs/ARCHITECTURE.md` — текущее устройство бота (как есть)
- `docs/ISSUES.md` — найденные баги/UX-замечания для обсуждения/фиксинга
- `docs/ROADMAP.md` — бэклог улучшений с приоритетами
- `docs/ENVIRONMENT.md` — ограничения и правила окружения
- `SPEC.md` — навигация по документации
- `README.md` — пользовательская документация
- `OPENCODE.md` — локальный (не трекается) файл с машинно-специфичными деталями

## Алгоритм работы
- **Ветка** - перед началом работы спрашиваю у пользователя, в какой ветке работать; базой служит `deploy`, новый функционал делаю в отдельной ветке
- **Маленькие шаги** - всегда одно небольшое улучшение или исправление за раз
- **Сначала предложение** - описываю суть изменения, для чего оно действительно нужно, возможные риски
- **Только после согласия** - вношу изменения только после явного одобрения
- **Коммиты обязательны** - после каждого логичного изменения делаю коммит в текущую рабочую ветку с понятным сообщением; сообщения коммитов — только на английском
- **Тесты** - использую `node:test`. После правок затрагивающих логику запускаю `npm test`. Если правка требует ручного тестирования в боте - **обязательно** дам пошаговую инструкцию: что ввести, какой результат ожидать, на чём тестировать (тестовый бот + тестовая таблица)
- **Всегда спрашиваю** - если что-то непонятно, нужны инструменты, доступы, права, секреты, или нужно посмотреть глазами в таблицу/код/протестировать с телефона - обязательно спрашиваю
- **Минимум правок** - только то, что согласовано
- **Фиксация** - всё важное фиксирую в `docs/ISSUES.md` или `docs/ROADMAP.md`

## Правила работы
- Работать только в рамках тестового стенда (отдельный бот + отдельная таблица)
- Не коммитить секреты (`.env`, `credentials.json`)
- Перед правками читать релевантные модули целиком
- Следовать существующему стилю: инжекция зависимостей через `deps`, `state` в виде Map, middleware для доступа
- Делаем минимальные осознанные правки
- Всё важное фиксировать в `docs/ISSUES.md` или `docs/ROADMAP.md`
- Тестируем локально перед тем, как предлагать изменения (с учётом правил из `docs/ENVIRONMENT.md`)

## Definition of Done
- `npm test` проходит.
- `npm run lint` проходит.
- Изменения отражены в `docs/` там, где это важно.
- Сделан коммит в рабочую ветку.

## Карта изменений
- Новая команда/кнопка меню → `src/handlers/`, регистрация в `src/bot.js`
- Новый шаг диалога `/add` → `src/handlers/addHandler.js`, `src/state.js`
- Inline-кнопка/клавиатура → `src/keyboards.js`, роутинг в `src/handlers/callbackHandler.js`
- Ввод суммы → `src/amount.js` (логика), `src/amountUi.js` (очередь рендера)
- Календарь/даты → `src/calendar.js`, `src/utils.js`
- Google Таблица → `src/sheets.js`
- Тексты сообщений → `src/messages.js`
- Доступ/конфиг → `src/config.js`, `src/utils.js`

## Ключевые файлы
- `src/bot.js`, `src/index.js`, `server.js`
- `src/config.js`, `src/sheets.js`, `src/state.js`, `src/utils.js`
- `src/handlers/*`, `src/keyboards.js`, `src/messages.js`, `src/logger.js`

## Команды
- `npm run dev` — локальный запуск с nodemon
- `npm start` — запуск через server.js (health-check на /health)
- `npm test` — запуск unit-тестов (node:test)
- `npm run lint` — проверка кода (ESLint)

## Особенности
- Auth Google: приоритет `GOOGLE_CREDENTIALS_B64`, fallback `credentials.json`
- Доступ: `ALLOWED_USERS` обязателен, проверяется в `config.js` при старте
- Диалог `/add`: date -> amount -> category -> wallet -> note (`-` для пропуска)
- Состояние хранится в памяти (Map), очищается по завершению/отмене
- Тестовый стенд: отдельный бот + отдельная таблица
